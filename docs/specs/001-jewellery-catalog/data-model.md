# Модель данных v0.2

[Правила проекта](../../../AGENTS.md) · [Основная спецификация](spec.md) · [Технический план](plan.md) · [Все задачи](tasks.md) · [Решения и открытые вопросы](review.md)

Статус: слой шаблонов, справочников и оформления реализован в схеме IndexedDB version(2) с миграцией из version(1). Q11/Q12 остаются открытыми; временные правила ниже не являются согласованными требованиями. JewelleryItem, Photo и BackupManifest описывают следующие задачи и пока не имеют таблиц хранения.

| Сущность | Основные данные |
| --- | --- |
| JewelleryItem | id, typeId, fieldSchemaSnapshot, materialIds[], stoneIds[], fineness, weightGrams, size?, notes?, customValues, createdAt, updatedAt |
| Photo | id, itemId, blob, mimeType, originalName, byteSize, order |
| TemplateField | id, source (builtin/custom), label, kind, enabled, required, protected, scope (all либо typeId[]), order |
| SnapshotField | поля TemplateField, unit?, options? |
| CreationTemplate | id = creation, revision, fields: TemplateField[] |
| CardSnapshot | templateRevision, typeId, typeLabel, sizeKind, fields: SnapshotField[], materials, stones |
| DictionaryEntry | id, kind (type/material/stone), label, enabled, revision, sizeKind? |
| AppearanceSettings / AppearanceRecord | themeMode (system/light/dark), accentTone (burgundy/forest/ochre); в базе также id = appearance, revision |
| BackupManifest | formatVersion, exportedAt, items, photoMetadata, creationTemplate, dictionaries, settings |

## Идентификаторы и прототип

- ID не зависит от подписи. Начальные ID типов: ring → «Кольца», earrings → «Серьги», chain → «Цепи», brooch → «Броши», other → «Прочее». Браслеты также включены в начальный справочник с ID bracelet. Добавление, переименование и удаление типов согласованы в Q09. Формат размера для новых пользовательских типов ещё требует решения в Q11, поэтому их создание в интерфейсе временно отключено; смена типа старой карточки описана в Q12.
- «Все» — фильтр интерфейса с ключом all, а не тип изделия и не запись справочника.
- В коде демонстрационная карточка именуется DemoJewelry: typeId и categoryLabel отделяют связь от отображения. Её name — подпись прототипа, а не обязательное поле реальной карточки. Демоданные не переносить в базу как пользовательские записи.
- Везде использовать accentTone, как в текущем коде. Поле accentId не используется. Для нескольких материалов использовать materialIds, а не одиночное metal/material.
- Общий редактор в настройках управляет тремя списками: типы изделий, материалы и камни. Для добавления/переименования достаточно названия и явного сохранения. В карточке меняется выбор, а не определение общего справочного значения.
- Переименование сохраняет ID. Новое значение получает новый ID, не вычисляемый из подписи. Название обрезается по краям, не может быть пустым; дубликаты активных названий в одном справочнике сравниваются без учёта регистра.
- Удаление после подтверждения устанавливает enabled = false, а не разрывает ссылки. Новые формы и новый выбор предлагают только активные значения. Старые карточки сохраняют выбранные ID и подписи из снимка; изменение другого значения не требует замены деактивированного варианта.
- Удаление типа изделия не удаляет его карточки или специальные определения полей. Такие карточки остаются доступны в общей коллекции. Глобальное переименование не переписывает подписи старых снимков; новый выбор значения использует актуальную подпись.
- Сохранение справочника проверяет revision и уникальность названия в транзакции. Ошибка или конфликт не теряют черновик и не перезаписывают более новую редакцию. Начальные списки заполняются только при инициализации, а не восстанавливают удалённые варианты при каждом запуске.

## Встроенные поля и значения

- Защищённые поля: фото, материалы, fineness, weightGrams, notes. Для сохранения видимых полей нужны хотя бы одно фото, хотя бы один материал, заполненная проба и положительный конечный weightGrams. Заметки необязательны. Пользователь не удаляет эти поля из шаблона, но может скрыть любое через enabled=false. Скрытые поля не включаются в новый снимок и не требуют заполнения.
- typeId определяет типовую схему при создании. Пользователь может менять typeId сохранённой карточки без добавления/удаления её полей. Поле type защищено от удаления, но его можно скрыть; required применяется только при его наличии в снимке; преобразование размера между разными форматами — в Q12. Не менять единицы существующего значения молча и не удалять значение при выборе нового типа.
- materialIds — несколько материалов, например белое и красное золото. stoneIds — несколько названий камней; вес, качество и прочие параметры каждого камня не входят в v1.
- Ввод веса поддерживает точку и запятую; пустое значение не равно нулю. NaN, бесконечность, ноль и отрицательные значения отклоняются.
- Формат размера задаёт sizeKind в справочнике типов и снимке: ring — положительное число для колец; length — положительное число в сантиметрах для цепей/браслетов; earring — small/medium/large для серёг (русские подписи в интерфейсе); none — отсутствие поля размера. Значение size в текущей доменной валидации — строка либо число, а не объект с дискриминатором. Примеры 16 и 16,5 не задают фиксированный шаг или диапазон. Для брошей/прочего встроенный размер пока не определён.
- Проба обязательна только при наличии поля в снимке; скрытое поле не требует fineness. Формат ввода уточняется в Q11; временно реализована непустая строка без фиксированного списка до ответа пользователя. Обязательность не означает, что значение обязано быть числом.
- Название, цена и валюта не входят в текущую модель пользовательской карточки.

## Дополнительные поля и снимки

- Пользователь создаёт только текстовое дополнительное поле: название и input. kind = text, required = false. Числовые и другие виды нужны только встроенным полям, в конструкторе не показываются.
- customValues — соответствие стабильного ID дополнительного поля строковому значению. Встроенные значения хранятся в свойствах JewelleryItem и не дублируются в customValues.
- Название поля после удаления пробелов по краям не может быть пустым. Переименование сохраняет ID; удаление и последующее создание нового поля с тем же названием создаёт новый ID.
- Шаблон хранит единый массив fields; scope = 'all' либо непустой массив выбранных typeId, а не отдельные commonFields/fieldsByType. Общая и специальная части собираются без дублей по ID. Отдельные исключения, скрывающие общее поле у одного типа, пока не согласованы.
- Шаблон сохраняется явно, целиком и атомарно, с проверкой revision. Новое поле добавляется в конец; order сохраняет прежний порядок; перестановки в интерфейсе нет. Разделы по умолчанию свёрнуты, checkbox справа управляет enabled каждого поля.
- fieldSchemaSnapshot — независимая копия состава полей, ID, подписей, видов, единиц, вариантов, порядка и обязательности на момент открытия формы. Изменение текущего шаблона не перестраивает открытую форму.
- Снимок содержит подписи типа и справочных значений для независимого отображения старой карточки. При изменении выбранных значений обновляются подписи именно этих значений, но не состав полей и не определения схемы карточки.
- У старой карточки разрешено изменять значения. Добавлять и удалять её поля, менять их тип или массово применять новый шаблон запрещено.
- Снимок и значения сохраняются одной транзакцией. Экспорт включает снимки старых карточек и действующий шаблон новых; сквозная работа с карточками относится к задаче 03, экспорт — к задаче 04.

## Хранение и перенос

- Настройки оформления в IndexedDB — источник истины; localStorage — производный кэш первого отображения. При первой инициализации перенести валидный старый кэш, включая JSON-строки. Если запись базы уже есть, кэш её не перезаписывает.
- После чтения/записи базы синхронизировать React-состояние и кэш. Сбой кэша не откатывает подтверждённую запись базы; сбой базы показывается без ложного успеха. Асинхронное начальное чтение не должно перезаписывать более новый выбор пользователя.
- Скрытие инструкции установки действует до перезагрузки и не входит в переносимые настройки (Q03).
- Фото принадлежат одной карточке, хранятся как Blob; внешние ссылки и base64 не заменяют оригиналы в резервной копии.
- Реализованы таблицы templates (ключ id), dictionaries (ключ id, индекс kind), settings (ключ id) в Dexie version(1). Версия 2 добавляет enabled=true прежним полям; ранее удалённые optional встроенные поля восстанавливаются в конце с enabled=false. ID, ревизии и прежние данные сохраняются; перенос старого localStorage выполняется при начальной инициализации оформления. Начальные справочники и шаблон создаются один раз транзакцией, без дубликатов. Миграции версионируются; очистка пользовательской базы ради исправления ошибки запрещена.
- Версия экспортного формата отделена от версии IndexedDB. Неизвестные версии не импортируются молча.

Реализованный доменный контракт отделён от UI: Zod проверяет шаблон и справочные записи, сборка CardSnapshot копирует поля и подписи, проверка значений отвергает неизвестные customValues и неверные обязательные значения. parseCardSnapshot принимает unknown, проверяет структуру снимка, уникальность ID/позиций/вариантов и определения полей; проверка значений сначала проверяет сам снимок. Исторические подписи и удалённые справочные ID не сверяются с текущими справочниками, отсутствие скрытых полей допустимо. Сохранение снимков с реальными карточками и смена их типа будут реализованы в задаче 03.
