# Модель данных v0.1

[Правила проекта](../../../AGENTS.md) · [Основная спецификация](spec.md) · [Технический план](plan.md) · [Все задачи](tasks.md) · [Решения и открытые вопросы](review.md)

Статус: проект модели; не готовая схема базы. Спорные поля не фиксировать миграциями до уточнения требований.

| Сущность | Основные данные |
| --- | --- |
| JewelleryItem | id, typeId, fieldSchemaSnapshot, metal (кратность уточняется), stoneIds[], fineness?, weightGrams?, size?, notes?, customValues, createdAt, updatedAt |
| Photo | id, itemId, blob, mimeType, originalName, byteSize, order |
| FieldDefinition | id, label, kind, required, unit?, options?, scope, enabled, order |
| CreationTemplate | revision, commonFields, fieldsByType — текущая форма создания новых украшений |
| DictionaryEntry | id, dictionaryKind, label, enabled |
| AppearanceSettings | themeMode, accentId |
| BackupManifest | formatVersion, exportedAt, items (включая снимки схем), photoMetadata, creationTemplate, dictionaries, settings |

Настройки оформления предлагается хранить в IndexedDB вместе с переносимыми данными; localStorage — только производный кэш для первого отображения. Состояние закрытия инструкции, если оно будет согласовано, относится к конкретному устройству и требует отдельного решения о переносе.

## Инварианты

- Идентификаторы стабильны и не зависят от названий. Переименование поля или справочного значения не меняет ссылки.
- Тип изделия, металл и хотя бы одно фото обязательны по текущей временной договорённости.
- Камни — множественный выбор видов; подробная модель отдельных вставок отложена.
- Проба — справочное/строковое значение, а не обязательное число: перечень и связь с металлом уточняются.
- Вес — положительное конечное число в граммах при наличии. Пустое значение отличается от нуля. В форме учитывается десятичная запятая.
- Размер зависит от типа изделия; единицы и система размера кольца требуют решения. Не хранить все размеры как безразмерное число.
- Название, цена и валюта отсутствуют в текущем наборе полей.
- customValues связывает ID определения поля с типизированным значением. Схема проверяет соответствие типа и разрешённых вариантов.
- Встроенные поля имеют стабильные системные ID и однозначное соответствие свойствам JewelleryItem. customValues содержит только дополнительные поля; одно значение не записывается одновременно в два места. Неактивное поле нового шаблона не требует скрытого значения при создании; ограничения обязательных полей остаются открытым вопросом.
- Предлагаемая структура снимка включает подпись типа изделия и подписи выбранных справочных значений. Одних typeId/stoneIds недостаточно для неизменного отображения после редактирования справочника. Для фильтрации сохраняются стабильные ID, для отображения старой карточки — её снимок.
- scope поля — все изделия либо набор typeId. Изменение шаблона не меняет существующие карточки.
- Предлагаемая реализация: при создании сохранять fieldSchemaSnapshot — независимый снимок объединённых общих полей и полей выбранного типа. Он включает ID, подписи, типы, единицы, варианты, порядок и обязательность. Источником отображения старой карточки служит снимок, а не изменяемый шаблон или справочник.
- Значения и снимок схемы сохраняются вместе с карточкой. Экспорт включает и снимки старых карточек, и актуальный шаблон для новых.
- Фото принадлежат одной записи, не хранятся в base64. Внешние ссылки на фото не заменяют содержимое резервной копии.
- Даты — технические метаданные; не добавляют пользователю обязательных полей.
- Версия экспортного формата отделена от версии IndexedDB. Неизвестные версии не импортируются молча.

## Изменение определений полей

Изменение шаблона, включая удаление поля, не мигрирует старые карточки. Предложение: редактирование старой карточки использует её снимок схемы и прежние правила валидации. Смена типа изделия в существующей карточке требует отдельного решения. Не реализовывать массовое применение нового шаблона к старым карточкам без отдельного требования.
