# Модель данных v0.6

IndexedDB v6 добавляет фиксированный тип `pendant` (Подвески, sizeKind=none). Порядок типов задаётся единым каталогом в коде, не порядком IndexedDB. Прежние записи и фото не меняются. Аналитика вычисляется из JewelryItem и не сохраняется отдельной таблицей: учитываются только украшения из одного известного металла и с указанным весом (несколько цветов золота допустимы); общий вес не пересчитывается в чистый металл.

IndexedDB v5 добавляет необязательный `materialFineness: Record<materialId, finenessId>` в JewelryItem и CardValues. Новые формы используют эту карту вместо общей пробы; каждому выбранному материалу соответствует одно значение, лишние ключи запрещены. При скрытом поле проб карта пустая. Старые записи с `finenessId` остаются без перезаписи: привязку общей пробы к нескольким материалам невозможно восстановить достоверно. Старый формат читается и отображается; редактор переводит его в карту, автоматически связывая пробу только с единственным подходящим материалом. При сохранении нового формата `finenessId` удаляется. Подписи всех выбранных проб остаются в options снимка; фото, ревизии и исторические снимки миграцией не меняются.

Изменения 2026-11-23: IndexedDB v4; DictionaryEntry получает необязательные metal (gold/silver/platinum, только для проб) и color (#RRGGBB, только для камней). DictionaryOption сохраняет эти атрибуты в снимке. Прежние данные без них валидны. Пробы уникальны внутри металла; новые ID: fineness-<metal>-<value>. Старые стандартные общие пробы деактивируются без удаления, пользовательские варианты сохраняются. Аметист/топаз добавляются без дублирования пользовательских названий. AccentTone дополнен blue.

## Справочники и поля

Типы фиксированы: ring, earrings, chain, pendant, bracelet, brooch, other. «Все» — фильтр all, а не запись справочника. Тип всегда видимый и обязательный. Материалы, камни и пробы редактируются в настройках; удаление деактивирует запись. ID не зависит от подписи, переименование сохраняет ID. Дубликаты активных названий сравниваются после обрезки пробелов без учёта регистра.

Пробы разделены на золото (375, 500, 585, 750, 958, 999), серебро (800, 830, 875, 925, 960, 999) и платину (585, 850, 900, 950, 999). Сохраняется materialFineness; подписи и металлы всех выбранных проб — в options поля снимка. Прежние снимки без металла остаются валидными. Для совместимости определения шаблона kind поля fineness остаётся text; фактический ввод — отдельный выбор для каждого материала, валидатор проверяет ID и соответствие металла.

Видимые фото, материалы, проба и вес обязательны; заметки необязательны. Защищённые поля нельзя удалить, но можно скрыть, кроме типа. Скрытые поля не попадают в новые снимки и не требуют значений. Фото не более пяти; первое — обложка, порядок хранится в photoIds. Размер необязательный: ring — положительное число, length — положительное число в сантиметрах, earring — small/medium/large, none — отсутствует. Брошь и прочее не имеют размера. Ввод чисел принимает точку/запятую, сохранённые значения — числа; ноль, отрицательные и нечисловые значения отклоняются.

Дополнительные поля только текстовые, необязательные; customValues связывает ID поля со строкой. Scope — all либо список typeId. Шаблон хранит единый массив полей и сохраняется явно целиком с проверкой revision.

## Исторические снимки

Снимок независимо копирует поля, подписи, варианты, порядок, единицы и обязательность на момент открытия формы. Изменение шаблона не перестраивает открытый редактор или сохранённую карточку. Старые значения справочников сохраняют исторические подписи даже после переименования/деактивации. Новый выбор проверяется по активному справочнику и получает актуальную подпись.

Исключение — явная смена типа: изменяется только формат размера, несовместимое значение очищается. Совместимая длина сохраняется. sizeEnabled запоминает видимость размера при переходе через тип без размера. Остальные поля исторического снимка не добавляются и не удаляются. Изменения происходят в черновике до успешного сохранения.

## Хранение и транзакции

Dexie: templates (id), dictionaries (id, kind), settings (id), items (id, typeId, createdAt), photos (id, itemId). Версия 2 добавляет enabled прежним полям и восстанавливает удалённые необязательные встроенные поля скрытыми. Версия 3 добавляет items/photos, включает обязательное поле типа, восстанавливает отсутствующие/деактивированные встроенные типы и добавляет недостающие начальные пробы. Пользовательские записи не очищаются. Начальные данные создаются транзакцией; обычная инициализация не восстанавливает удалённые материалы, камни и пробы.

Фото принадлежат одной карточке. Оригинальный Blob хранится без сжатия и перекодирования вместе с размерами декодированного изображения. Метаданные коллекции читаются отдельно от Blob; видимые изображения получают object URL, который освобождается при уходе из области просмотра или размонтировании.

Сохранение карточки, добавление и удаление её фото выполняются атомарно. Удаление карточки удаляет её фото в той же транзакции. Проверяются revision, принадлежность фото, ссылки и ограничения. Конфликт двух вкладок не перезаписывает новую редакцию. Ошибка записи сохраняет заполненную форму; подтверждённый выход уничтожает черновик, постоянного хранения черновиков нет.

Данные на границе проверяются Zod и доменными валидаторами; снимки проверяются независимо от текущего шаблона. Настройки оформления в IndexedDB — источник истины, localStorage — производный кэш. Отказ кэша не откатывает базу. Скрытие инструкции установки действует только до перезагрузки.

Формат резервной копии имеет собственную версию и включает снимки, справочники, шаблон, настройки, цены металлов и оригиналы фото. Экспорт и атомарная замена реализованы в backup-repository; описание v1 ниже.

### Версия 7 — цены аналитики
Новая таблица metalPrices с ключом id (gold/silver/platinum), pricePerGram (положительное число либо null для отсутствующей цены), revision. Остальные таблицы и снимки не изменяются. Производные стоимости не хранятся. Запись проверяется во время чтения и атомарного сохранения с контролем revision.


### Версия 8 — восстановление коллекции
Таблица restoreState: запись id=generation и неотрицательное целое value. При полной замене поколение увеличивается в той же транзакции; открытый редактор карточки удерживает исходное поколение и не может записать черновик после восстановления. Ревизии импортируемых изменяемых сущностей назначаются выше текущих и импортируемых значений; содержимое исторических снимков и байты фотографий сохраняются. restoreState не переносится между устройствами.

Формат резервной копии v1: manifest.json, format=jewellery-box, version=1, exportedAt, template, dictionaries, settings, items, metalPrices, photos. Оригиналы располагаются в photos/<index>.bin, метаданные включают path и SHA-256. Поддерживаются только ZIP-записи без сжатия, выпущенные приложением; предел архива 256 МиБ, JSON 10 МиБ, 10001 файл. Эти защитные пределы не подтверждают возможность обработки такого объёма на iPhone.
