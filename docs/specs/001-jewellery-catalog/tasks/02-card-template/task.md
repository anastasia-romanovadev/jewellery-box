# 02. Шаблон создания карточек

[Правила проекта](../../../../../AGENTS.md) · [Основная спецификация](../../spec.md) · [Технический план](../../plan.md) · [Модель данных](../../data-model.md) · [Все задачи](../../tasks.md) · [Решения и открытые вопросы](../../review.md)

Статус: черновик. Зависимость: [01 — основа, дизайн и навигация](../01-foundation/task.md).

## Результат

Редактор формы создания в настройках: общие поля и поля по типам изделий. Изменения действуют только на новые карточки.

## Уточнить

Статусы вопросов: [Q07–Q13 и D03–D04](../../review.md).

Типы дополнительных полей, обязательность, редактирование справочников, несколько металлов и параметры камней, единицы размеров. Поведение при редактировании старой карточки и смене типа изделия.

## Шаги

- [ ] 02.1. Согласовать типы полей, ограничения и правила валидации.
- [ ] 02.2. Описать стабильные ID, общие/специальные поля и снимок схемы карточки.
- [ ] 02.3. Подготовить Dexie, миграцию и слой данных шаблонов/справочников.
- [ ] 02.3a. Добавить канонические настройки оформления в IndexedDB и согласование с кэшем темы. Подключить fake-indexeddb; проверить транзакции и подготовить проверки миграций.
- [ ] 02.4. Реализовать добавление, изменение, удаление из шаблона и порядок полей.
- [ ] 02.5. Реализовать сборку схемы по типу изделия и независимый снимок для карточки.
- [ ] 02.5a. Сохранять обязательность, единицы и справочные подписи в снимке; исключить дублирование встроенных значений в customValues. Определить поведение уже открытой формы при изменении шаблона.
- [ ] 02.6. Проверить валидацию, перезапуск, ошибки хранения и неизменность старых схем.

## Приёмка

AC-07. Общие поля применяются ко всем типам, специальные — к выбранным. Переименование не меняет ID. Изменение шаблона не меняет снимки существующих карточек; интеграционная проверка с карточками повторяется в задаче 03.

Вне задачи: массовое применение шаблона к старым записям, универсальная платформа форм.
